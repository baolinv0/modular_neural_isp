# TM PGT IQA V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the V2 front-portrait TM pseudo-GT generator, evaluator, semantic selector, reports, and offline tests.

**Architecture:** Preserve the existing source-aware Qwen judge and replace the candidate-only CLI with a batch V2 pipeline. Candidate manifests carry identity and family metadata into objective scoring, family-balanced Top-K, Qwen tournament, final selection, and visual reports.

**Tech Stack:** Python, NumPy, Pillow, standard-library HTTP, optional PyYAML and Qwen-compatible image-edit API.

**Spec:** `docs/superpowers/specs/2026-08-29-tm-pgt-iqa-v2-design.md`

## Global Constraints

- Retinex is deterministic and retained as the eight-level primary search axis.
- All thresholds and score weights are configurable; no learned IQA or additional generic NR-IQA metrics.
- No pool spread/outlier rule may lower PGT quality by itself.
- Qwen is an optional judge; live conformance remains `NOT COMPLETE`.
