# Apple/Samsung physical acquisition data pipeline

The user approved the in-chat design and requested implementation on `feature/capture-tm-c-20261005`.

## Goal
Generate physically differentiated single-exposure Apple and sequential three-exposure Samsung training records, integrate them into existing factorial AE/TM training, and export reusable RAW plus fixed targets. This is a relative-radiance simulator, not measured phone calibration.

## Contracts
- Existing `Scene`, `SensorProfile`, `CaptureAction`, and legacy RGB paths stay supported.
- Add `AcquisitionProfile` in `capture_tm/acquisition.py`: `cfa_pattern='RGGB'`, `spatial_downsample=1`, `readout_s=.001`, `rolling_shutter_s=0`, `input_stage='post_optics'`, optional `psf_kernels=None`. No new PSF on post-optics input. Native Bayer DN is retained; bilinear demosaiced camera RGB bridges existing TM/fusion.
- `capture_raw(scene, action, sensor, *, acquisition=None, center_s=0., seed=0, noisy=True)` returns a `RawCaptureResult` (CaptureResult-compatible `rgb`, `noise_variance`, `saturation_mask`, `action`, `metadata` plus `raw_dn`, `raw_noise_variance`, `raw_saturation_mask`). Noise is applied to actual CFA samples before demosaic. Optical processing precedes temporal linear integration, pixel-area reduction, CFA, photons/full-well, read noise, analog gain, ADC noise/black/quantization/clipping. Digital capture gain must be 1 for new datasets. Variance validity is declared.
- `prepare_scene(scene, acquisition)` applies PSF (only pre-optics) and spatial area reduction without changing per-pixel relative intensity. Its reference at time 0 is fixed after optics and pixel area, before finite shutter/noise, so all candidate actions share geometry and target. Record native/source resolution and source limitations.
- Source recipe importer in `capture_tm/pipeline_sources.py` writes existing v1 scene manifests. Explicit linear sensor RGB/XYZ and layouts, strictly increasing float64 time, one scale per scene, float EXR/NPY/NPZ/TIFF arrays or explicit sequences. Existing RGB16 proxy import commands remain available separately. Group original source/dependency identities before augmentation. No JPEG-to-HDR claims or inferred photometric domains.
- `pipeline.py` generates a v2 archive JSON with `kind='capture_tm_acquisition_dataset'`, `sensor`, `acquisition`, `schemes`. `schemes[scheme]` has `plans` and `records`; rows have `scene_id`, `source_id`, `split`, `source_kind`, `provenance`, relative `path`. Each `.pt` record has `previews`, `state`, `preview_metadata`, `rule_index`, `sharp_reference`, `target`, `subject_mask`, `images` [R,K,3,H,W], `reliability` [R,K,1,H,W], `missing` [R,K,3,H,W], `capture_ev` [R,K], `radiance_mse` [R,K], `noise_seeds`, `num_plans`, `render_ev`, and native `raw_dn` [R,K,F,1,H,W], raw variance/masks, plus action/readout metadata. Paths relocatable. Seeds stable by scene identity, split, repeat, candidate/frame. Dataset writes do not overwrite existing outputs and manifest commits only after successful generation.
- Fixed existing bank: shared 100 ms acquisition window, single reference t=0. Validate full rolling exposure + readout inside frame slot/window. Historical previews end before all final candidates begin. Static singleton allowed explicitly; dynamic scenes never clamp/extrapolate.
- `joint_experiment.run_factorial` auto-detects v1 scene or v2 acquisition manifest. For v2, prepare frozen TM coefficients from archived images with no recapture, maintaining A00/A10/A01/A11 and S00/S10/S01/S11. Checkpoints bind sensor/plans/acquisition. Scene/reference/target never enter policy inputs.
- `pipeline_cli` supports demo/import/generate/validate; JSON recipes and acquisition configs. Dataset and validation reports contain calibration/proxy limits. Existing shipped ISP weights used.

## Verification
Test photon-vs-gain, real Bayer pattern/channel phase, no pre-integration clipping, temporal movement, PSF stage, downsampling, rolling readout ordering and no future preview leakage. Test source split grouping/domain/time, moving archive paths and all eight factorial training groups. Generate a small CPU dataset, validate it, train all groups for one epoch, independently review.
