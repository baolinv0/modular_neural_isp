# AE–TM GitHub 半自动科研闭环：首轮实施计划

日期：2026-10-07。依据：用户提供的帖子全文和现有代码，源基线 `49e158ac663498a622107dd2f306f38d8f1a47a9`。

## 设计

复用已有 GPU 端 coding-agent。联网端负责研究决策与审核，执行端只在给定任务和预算内修改代码、运行实验、提交结果。GitHub 保存代码、小型证据与决策；数据、权重和完整缓存不上传。此包不实现LLM服务、agent harness、GPU调度器或自动投稿。

## 接口

- `tools/bridge.py`：读取JSON命令卡，执行显式argv、限时、失败即停止、保存run.json与日志；汇总成不带科学结论的回传包。
- `tools/preflight.py`：仓库入口检查、实际CUDA探测、S24 train/val配对及采样文件头/元数据检查。缺失条件返回blocked，绝不伪造数据。
- 现有训练代码不变。CUDA迁移、S24数值域接入、强基线属于后续执行任务，不伪装为本包已经实现。

## 实施顺序与验收

1. 先写测试：超时、子进程失败、重复输出、NaN/无效预算、数据缺项、PNG8误标RAW、配对冲突、未提供数据、仅CPU入口。
2. 实现最小runner与预检。仅标准库；PyTorch探测在独立子进程中可选执行。
3. 测试通过后，以临时测试夹具演示run→packet，明确它不是AE–TM实验。
4. 写R0–R3任务卡、研究骨架、模型启动prompt、GitHub往返命令。
5. 独立复查文件、命令、测试与声明，生成ZIP和可应用补丁。

## 首轮约束

- R0默认不训练，不读取test图像。
- 历史toy smoke单独手动调用；历史test指标不用于新研究调参，重看后只能标记为诊断集。
- 所有运行记录提交号、任务副本、命令、退出码与时间；这不是防篡改审计系统。
- 模型输出不是测量；已验证软件不等于已验证算法收益。
- 长训练不得仅由研究大纲自动触发，须有确定配置与预算。
