# 项目级执行规则

适用范围：本研究工作流以及明确委派给它的capture_tm修改。不要覆盖仓库原有AGENTS/CLAUDE规则；如发生冲突，停止并报告。

## 研究合同

先读取START_HERE、RESEARCH、当前task和最近一次报告。事实必须指向文件/命令/结果；解释另列；不写不存在的实验数值。研究大纲是待证伪结构，不是必须得到正收益的目标。

GT定义、train/val/test、有效mask、主要评价、动作/时序/预算、baseline容量不可为提高分数而静默更改。修改这些条件必须提交独立提案，并且旧协议保留为对照。正式test只能在冻结确认后使用；历史已看过的数据标为diagnostic，不冒充全新holdout。

## 执行权限

可自主：任务范围内读写代码、写测试、修接口、调整明确允许的batch/chunk以避免OOM、执行任务预算内命令、整理报告。语义等价的工程改动须有回归证据；影响batch统计/优化轨迹的改动不是自动等价。

须上报：同一故障两次修补仍失败；发现指标/GT/数据域问题；任务预算不足；所有基线相近或方向被简单方法解释；需要更换网络/损失/任务；需要访问test、上传公司材料、公开数据或大规模训练。

有限重试，不无限自我修复。OOM先定位是LLM占卡、缓存、候选渲染还是训练激活；不能先把数据/分辨率改小后冒称同实验。允许用更小smoke定位，但单独命名。

## 证据

每次正式对比需要：代码提交、数据协议、配置、seed、run目录、执行退出码、逐场景指标、实际时间与资源。记录git提交即可，不建设复杂哈希/记忆平台。脏工作区只能用于debug；正式对比先提交代码，并指明完整实验配置。

程序退出成功 != GPU训练成功 != 数值正确 != 科研收益。模型预测的分数、补写的日志与生成图不能充当实测。

## 模型和GPU

模型API不是完整执行器；必须在具备文件编辑、shell、运行日志能力的现有coding-agent中使用。优先复用公司现成宿主；没有时可配置Qwen Code。

不得假定4×96GB可以透明合并为单卡384GB。初期优先单卡独立实验，不先做DDP或新调度器。GPU分配由用户/现有队列确认，避免和LLM推理互相抢占。

## GitHub

本仓库公开。只提交获准公开的代码、配置、小型统计和去敏失败样例；数据、权重、完整cache、模型key与内部资料不提交。

同一集成分支先只设一名写入者；并行实现另开分支，不让多个agent同时修改一个目录。不要`git add .`、force push或自动合并main。成功回传后等待下一轮任务，而不是擅自扩展课题。
